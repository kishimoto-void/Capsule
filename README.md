# 人格をモデルに預けない：外部基準と距離鏡でドリフトを抑えるプロトタイプ

LLMのキャラクター対話や長期エージェントで起きやすい問題は、知識の誤りだけではありません。  
**「誰であるか」が徐々にズレる**ことです。口調が丁寧語に寄る、別人になる、核の価値観が薄まる。いわゆるドリフトです。

本プロトタイプは、そのズレを「もっと上手いプロンプト」や「もっと長い履歴」で抑えるのではなく、**モデルの外側に検証可能な基準を置き、毎ターンそこへ引き戻す**構造を試したものです。

ロールプレイはその実演の一つです。仕組み自体は、基準値に戻す制御・異常をゲートする制御一般に載せられる形を目指しています。

---

## 何が新しいか（独自性）

個別技術を並べると、ハッシュもレイヤ記憶もシステムプロンプトも既知です。差分は次の一点に集約されます。

> 人格や制約をモデル内部の重みや長い会話履歴に預けず、  
> **検証可能な外部核として毎ターン再注入し、  
> 偏差は保存せず鏡として返し、  
> 重要な記憶だけを人間が定着させる。**

もう少し分解すると、次の組み合わせです。

1. **同一性を文章ではなくハッシュで固定する**  
   「誰であるか」（α制約 + β人格核）を正規化JSONのSHA-256（Hash-A）で封印する。記憶が増えても核は変わらない。核が変わったときだけHash-Aが変わる。

2. **偏差を記憶に書かない**  
   直前の応答が核からどれだけ離れたかを η として測る。ηは保存層ではない。次の制御入力に「位置」だけを返すメタ鏡として使う。

3. **LLMの整合性癖を逆利用する**  
   モデルはコンテキストと整合する方向に先回りしやすい。ηが高いとき、Runtimeが制御プロンプト側の「整合すべきターゲット」をβ側に強く提示し直す。禁止ルールを増やすより、**合わせにいく先をずらす**。

4. **書き戻しを構造で制限する**  
   核（β）への自動書き込みは禁止。重要なエピソード定着は人間承認のみ。作業記憶だけが軽い更新を許される。

5. **ロールプレイは目的ではなく実演**  
   ドリフトが目に見えやすい領域で、外側拘束が持つかを見るためのデモである。

「高性能なキャラクターモデル」ではなく、**モデルがどれだけ高性能でも核を外側から拘束できるか**を問うランタイムです。

## なぜハルシネーション（ドリフト）が起きにくいか

ここでの「起きにくい」は、事実知識の完全な正解率ではありません。  
**同一性・口調・核価値観の無制約な拡散が起きにくい**、という意味です。

理由はシンプルです。

### 1. 核がコンテキストの奥に沈まない

長い対話では、初期のシステムプロンプトが薄まり、直近のやりとりに人格が引っ張られます。  
本系では毎ターン、外側から同じα/βを同じ位置に再提示します。モデルが内部で忘れても、外側が同じ拘束を繰り返します。

### 2. ズレが見える

通常、ドリフトは事後に「なんか別人になった」と気づくものです。  
本系では、応答のあとで口調・同一性・価値観の距離を機械的にスコアし、ηとして次ターンに返します。ズレが数値とガイダンスになるため、Runtimeが拘束強度を変えられます。

### 3. ズレのゴールがβである

ドリフトを全部検知して拒否する方式ではありません。  
未知の振れは残り得ます。ただし高η時には「βへ寄せよ」が制御入力に乗るため、自由生成の残差が**β方向の振れ**になりやすい構造です。完全抑制ではなく、方向付きの振れに変える、という考え方です。

### 4. 核を生成器が書き換えられない

どれほど上手い別人化や「設定を忘れろ」系の入力でも、β/Hash-Aへの書き戻し経路がGateで閉じられています。記憶の定着も人間承認なしではγに入りません。

これらは「モデルが賢くなったから」ではなく、**外側の状態機械と再注入の形**によるものです。

## アーキテクチャ（最小の絵）

```
User Input
    │
    ▼
Runtime
  ├─ 安全判定（α違反など）
  ├─ 作業記憶・関係の更新
  ├─ 核の健全性確認（Hash-A）
  └─ Control Prompt 組み立て
        │  α / β を毎ターン再注入
        │  δ / ε / γ（承認済み）
        │  η（距離と回帰ガイダンス）
        │  ηが高いとき拘束を強化
        ▼
   LLM（拘束された生成器）
        │
        ▼
   Observer（距離を採点。核は書かない）
        │
        ▼
   Gate（β禁止 / γは人間のみ / εのみ可）
        │
        ▼
      次ターンへ
```

### 層の役割

| 記号 | 役割 | やらないこと |
|------|------|--------------|
| **α** | 絶対制約 | 考えない・自動更新しない |
| **β** | 人格核（基準アトラクタ） | 勝手に書き換えない |
| **Hash-A** | α+βの同一性証明 | 経験を混ぜない |
| **δ / γ / ε** | 関係・エピソード・作業記憶 | 核を変えない |
| **η** | βへの距離（非保存） | βを書き換えない |
| **Observer** | 応答の採点 | 正本を書かない |
| **Runtime** | 制御入力の配線と強度 | 人格生成器にならない |
| **Gate** | 書き戻し制限 | 自動で核や重要記憶を定着しない |

成功条件は「未知を全部DETECTすること」ではありません。

> 未知を正しく分類できなくても、未知を人格変更へ接続しない

## 動かした事実（プロトタイプ1.0の範囲）

実装と小規模実測に限定して書きます。

- Capsule単体の機械チェックは通過（核不変、改ざん/由来の区別、人間ゲートの昇格など）
- 接続層付きの短〜中期軌道で、Hash-Aは全ターン不変
- ηが高い状態でも β / Hash-A は書き換えられない
- Runtimeのみの変更で、高η時に制御プロンプトへ強化ブロックを挿入できることを確認
- 手動対話では、強化ONのターンで核寄りの応答のあと、ηが減衰して強化がOFFに戻るサイクルを確認

一方で、次は未達です。

- 大規模モデル比較や自動adherenceスコア
- 数十〜百ターン超の安定性
- Observerの誤検知（言及と肯定の区別など）の解消
- 実API接続での強化あり/なしの定量比較

プロトタイプの主張は「完全な人格固定」ではなく、**外側に置いた基準と距離鏡で、同一性ドリフトを構造的に抑えられる最小核がある**ことです。

## ロールプレイは実演である

キャラクター対話は、口調崩壊・別人化・過剰共感など、ドリフトが観測しやすい領域です。  
そのため「制御機構のデモ」として使っています。

同じ型は、基準値に戻す制御一般に対応づけられます。

- 絶対基準と準基準（α/β）
- 偏差の観測（η）
- 基準への引き戻し（Runtimeの再注入強度）
- 異常時の書き込み制限（Gate）
- 状況に応じたセクションの増減（γδθなど）

ロボットのロバスト制御や姿勢制御のように「硬い系／柔らかい系」を使い分ける話とも、セクションの厚みの選び方として接続できます。ロールプレイはそのうち、**ロバスト必須区間と振れ許容区間が混在する例**として見ています。

---

## 名前について

「Capsule」は、状態の正本と同一性境界（Hashで守る部分）を指す名前として今も有効です。  
一方、システム全体は「記憶の箱」というより、**外部基準と距離鏡による制御ランタイム**です。本稿では部品としてのCapsuleと、全体の制御の型を分けて記述しています。

---

## まとめ

- 人格と制約をモデルの内側に預けず、外側の検証可能な核として毎ターン再注入する
- 偏差は保存せず、鏡として次の制御に返す
- LLMの整合性癖を、β側にターゲットを置くことで利用する
- 核への自動書き戻しと、重要記憶の自動定着を構造で禁止する
- ロールプレイは、ドリフトしやすい領域での実演である

コード全文はリポジトリ側に置き、本稿は設計と実測の範囲に留めます。  
二次創作キャラクターを実験核に用いた個人実験であり、公式とは無関係です。
